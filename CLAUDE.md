# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`cost-anomaly`: a CLI that pulls 90 days of AWS Cost Explorer data (DAILY, grouped by SERVICE, `UnblendedCost` + `NetAmortizedCost`, `RECORD_TYPE` ∈ Usage/SavingsPlanCoveredUsage/DiscountedUsage) and flags per-service daily cost spikes using a robust median + MAD baseline. Results go to a CSV. The README and user-facing docs are in Vietnamese.

## Commands

```sh
uv sync                                        # install deps (Python >=3.11, boto3; pytest in dev group)
uv run pytest -q                               # all tests
uv run pytest tests/test_detect.py -q          # one file
uv run pytest tests/test_cli.py::test_end_to_end_writes_csv -q   # one test
uv run python demo/run_demo.py --end-date 2026-10-15             # offline end-to-end demo
terraform -chdir=infra/terraform init -backend=false && terraform -chdir=infra/terraform test   # Terraform unit tests (mocked, no credentials)
```

No linter/formatter is configured.

## Safety constraints (enforced in `.claude/settings.json`)

- Never run `terraform apply`/`destroy`/`plan` against real AWS (also denied in settings). Terraform is checked with `terraform -chdir=infra/terraform fmt -check -recursive`, `validate` and `test` only; tests use `mock_provider "aws"` in plan mode.
- Never run the real CLI (`cost-anomaly`, `uv run cost-anomaly`, `python -m cost_anomaly`, `run.py`) or the `aws` CLI: they need MFA and each Cost Explorer request costs $0.01. The user's shell exports `AWS_PROFILE` (aws-vault `credential_process`), so even an argument-less run starts real auth; to check `run.py`/CLI behavior use `--help` only, or unset `AWS_PROFILE` and point `AWS_CONFIG_FILE` at a temp file. Use the test suite or `demo/run_demo.py` to exercise the pipeline.
- Don't read `~/.aws/**`, `.env*`, top-level `*.csv` (e.g. `anomalies.csv` holds real account cost data), or the `*_report.html`/`*_report.md` written next to them (same data).
- Tests must never touch Slack: `conftest.py` deletes `COST_ANOMALY_SLACK_WEBHOOK`; CLI tests monkeypatch `urllib.request.urlopen`.
- Tests must never touch real AWS: `tests/conftest.py` has an autouse fixture that sets dummy credentials and points `AWS_CONFIG_FILE` at a temp path. AWS responses are faked with `botocore.stub.Stubber` plus JSON fixtures in `tests/fixtures/`.

## Architecture

`cli.main`: `assume_role_session` → `pipeline.run(session, settings, today)` (`compute_windows` → `install_guard(ce client)` → `fetch_daily_costs` → `to_matrix` once per metric → `detect`) → `write_csv`. `pipeline.run` takes any authenticated session, prompts for nothing and writes nothing, so scheduled runners can reuse it. Local problems (`ConfigError`, a non-Slack `COST_ANOMALY_SLACK_WEBHOOK`, corrupt `--state` → `StateError`) are checked before auth and exit 2. Errors from auth/fetch (`AuthError`, `BotoCoreError`, `CostExplorerError`, `TooManyPages`) exit with code 2 and no CSV is written. After the CSV/reports, if any of `--state`, the webhook env, `--alert-dry-run`, `--fail-on-anomaly` is used, `alerting.process` runs (below). Exit codes: 0 ok, 1 something new with `--fail-on-anomaly`, 2 errors above (or `--pdf` failed), 3 Slack delivery failed.

**Least-privilege auth (`auth.py`, `guard.py`)** — the tool does not use boto3's built-in assume-role or credential cache. It reads `role_arn`/`source_profile`/`mfa_serial`/`external_id`/`duration_seconds` from the profile itself, prompts for MFA on every run, and calls `sts:AssumeRole` with a **session policy** that allows only `ce:GetCostAndUsage`, so even an admin role yields CE-read-only credentials. `--with-cad` widens both to `guard.CAD_OPERATIONS` (+`GetAnomalies`): `auth.session_policy(operations)` builds the STS policy from the same set the guard uses, so the layers can't drift. As a second layer, `install_guard` hooks botocore's `provide-client-params` event (the first event fired, before signing or sending) and raises `ForbiddenOperation` for any operation outside an allowlist. STS clients allow `AssumeRole` only; CE clients allow `GetCostAndUsage` only. Keep both layers when adding AWS calls. `assume_role_session` takes injectable `prompt` and `session_factory` for testing.

**Date windows (`dates.py`, `config.Settings`)** — all windows use Cost Explorer's half-open `[start, end)` semantics. Fetch `[today-90, today)`. The 7 settled days ending T−3 are evaluated (`--eval-days`), plus the 2 most recent days (still settling in CE) as `Windows.provisional_days`; anomalies on those get `provisional=True`. `--no-provisional` (`Settings.include_provisional=False`) drops them. CE's `Estimated` flag is deliberately ignored (it can cover the whole open month). Each evaluated day is compared against the 30 days immediately before it. `cli.MAX_EVAL_DAYS` (lookback − baseline − excluded = 58) caps the settled `--eval-days`; argparse rejects values outside 1–58 before any AWS call. `compute_windows` raises if the lookback can't cover the earliest baseline.

**Fetch/transform** — `fetch_daily_costs` follows `NextPageToken` up to `max_pages` (cost guard), then raises `TooManyPages`. `to_matrix(results, start, end, metric)` pivots one metric into `{service: {day: cost}}` (a group missing the metric counts as 0). It sums amounts per (service, day), because a day can be split across pages, and it zero-fills missing days, because CE omits zero-cost groups.

**Detection (`detect.py`)** — two measures per service/day: usage (`UnblendedCost`; Savings Plan covered usage at on-demand-equivalent cost, RI-covered usage $0) and amortized (`NetAmortizedCost`, what was paid). `score_pair` scores both and counts a baseline day as history if either measure is > 0, so a fully RI-covered service is not "new". A row comes from the usage measure if it flags (`metric="usage"`), otherwise from an amortized SPIKE (`metric="amortized"`); never two rows. `driver(su, sa, driver_tolerance)` is `usage` iff both deltas are > 0 and ΔA is within ±25% of ΔU, else `rate`; NEW_SERVICE is always `usage`. `detect(matrix, eval_days, settings)` without `amortized` behaves exactly as before. Per measure:
- If the baseline has fewer than `min_history` (7) non-zero days, the day is a `NEW_SERVICE` when cost ≥ `new_threshold`. Note that a newly appearing service keeps being flagged daily until it accumulates 7 days of history.
- Thresholds are per service: `Settings.for_service(name)` applies `[services."name"]` overrides from the TOML `--config` (`settings_file.load_config`; precedence: built-in → `[defaults]` → explicit CLI flags, which default to `None` → per-service). `ignore` services are skipped everywhere; `known` services get `Anomaly.known=True`. Config errors (`ConfigError`) exit 2 before auth.
- Otherwise robust z = (cost − median) / `robust_scale`, where `robust_scale = max(1.4826·MAD, 1% of |median|, 0.01)` so flat baselines don't divide by zero. The day is a `SPIKE` only if z > `k` (3.5) **and** delta ≥ `min_delta` ($10). It is a `DROP` if median ≥ `drop_min_median` ($10), cost ≤ `drop_ratio` (10%) × median and z < −k; `detect()` emits a DROP only when the amortized measure drops **and** the usage measure drops too (or has median 0, i.e. fully RI-covered), so SP/RI purchases are not outages. `--no-drop` disables it.
- Every anomaly gets `month_impact = delta × dates.days_left_in_month(day)` (inclusive; negative for DROP).

**Output** — `report.write_csv` sorts rows by (date, delta) descending. `robust_z` is blank for `NEW_SERVICE`; then `metric`, `driver`, `provisional`, `month_impact`, `known`, `cad_match`. Report rows carry Vietnamese `labels` ("do giá/coverage", "tạm tính", "đã biết"); `Report.excess` excludes DROP deltas. Unless `--no-report`, the CLI also writes `<output stem>_report.html` and `.md`:
- `analysis.build_report` is the single source for both. It re-scores cells with `detect.score_pair`/`classify` (picking the measure named by `Anomaly.metric`) (the same math as detection, so explanations and chart thresholds can't drift from it) and produces per-row explanations, per-service rollups (consecutive-day runs, ongoing on last eval day), near misses (unflagged days filtered by `min_delta`/`k`/`new_threshold`), chart series, and insight/next-step text.
- `html_report` renders a self-contained page: inline CSS/JS, charts drawn client-side from a JSON `<script>` block (escape `</` there; service names are untrusted, also in `data-*` attributes and filter `<option>`s). `SECTIONS` lists (id, nav label, renderer); a section and its nav link appear only when the renderer returns text. A `<head>` script applies the saved theme (`localStorage['cost-anomaly-theme']`, try/catch) before first paint; the sticky top bar has the light/dark toggle and "Xuất PDF" (`window.print()`). Anomaly rows carry `data-*` keys for client-side filter/sort, each followed by a print-only `tr.why-row` (the explanation on its own line on paper). `@media print` forces light tokens, hides `.topbar`/`.js-only`, shows filtered rows and restores CSV order on `beforeprint`. `md_report` renders the same content minus charts.
- `--pdf` (`pdf.py`): `find_browser` (`$COST_ANOMALY_BROWSER` → Chrome/Chromium/Edge on PATH → macOS app bundles) runs in the fail-fast block before auth; `write_pdf` prints the written HTML with `--headless --print-to-pdf` and a temp profile via `subprocess` (no Python dependency). A print failure keeps CSV/HTML/MD, alerting still runs, exit 2 (3 wins). The Lambda never makes PDFs. Tests fake `cli.find_browser`/`cli.write_pdf`; `conftest.py` deletes `COST_ANOMALY_BROWSER`.
- All report prose is Vietnamese, matching the README.

**AWS CAD (`cad.py`, `--with-cad`)** — `pipeline.run(..., with_cad=True)` calls `GetAnomalies` for `[first eval day, last eval day]` after the cost fetch, parses root-cause services (fallback `DimensionValue`; open anomalies have `end=None`) and sets `Anomaly.cad_match` via `cad.match`. CAD errors never fail the run: they land in `RunResult.cad_error`, the CLI warns, the report shows "không lấy được". `cad_match` is `None` (empty in CSV) whenever CAD wasn't checked. Report section "Đối chiếu AWS CAD" uses `Report.cad_both/cad_tool_only/cad_only`; incidents carry `cad_match` (optional key in state JSON).

**Scheduled run (`lambda_handler.py`, `infra/terraform/`)** — `handler` → `run_scheduled(env, session, now)` with the execution role's credentials (no AssumeRole/MFA, so no session policy: least privilege is the role's own ARN-scoped inline policy, built with `jsonencode` in `locals.tf` so mocked-provider tests can decode it). Order: config from `COST_ANOMALY_CONFIG` (TOML text, `settings_file.parse_config`) → webhook from SSM (`SLACK_WEBHOOK_PARAMETER`, validated) → `S3StateStore.load()` → `pipeline.run` → CSV/HTML/MD to `s3://STATE_BUCKET/REPORT_PREFIX<date>/` → `alerting.process(..., state=preloaded)`. Clients are guarded: S3 {GetObject, PutObject}, SSM {GetParameter}, CE as in the CLI. Terraform disables Scheduler and async-invoke retries (each retry re-bills CE) and sets reserved concurrency 1. Terraform never touches the webhook value.

**Incidents and alerts (`state.py`, `alerting.py`, `alert.py`)** — `state.merge` folds anomalies into incidents keyed by (service, kind), merging runs of consecutive days that touch an existing incident; it prunes incidents ending before `fetch_start` and returns `Change(incident, "new"|"worse")` (worse = |peak| ≥ 1.5 × last alerted and +≥ service `min_delta`; `known` never changes). `alerting.process(anomalies, settings, fetch_start, store, deliver, now, save)` loads → merges → calls `deliver(changes)` → `mark_alerted` → saves; if `deliver` raises `AlertError` nothing is saved, so the alert is retried next run. Stores implement `load()/save()`: `LocalFileStore` (atomic write, versioned JSON via `state.dumps/loads`) and the CLI's `MemoryStore` when there is no `--state`. `alert.send` posts to the webhook with stdlib `urllib` (timeout 10 s, 3 attempts, retry on network/429/5xx), validates the host is `hooks.slack.com`, and never puts the URL in messages; it looks up `urllib.request.urlopen`/`time.sleep` at call time so tests can replace them. `build_message` escapes `& < >` in service names (untrusted).

## Tests and demo

`tests/conftest.py::results_from_matrix(matrix, amortized=None)` builds CE `ResultsByTime` payloads from `{service: {day: cost}}` dicts (amortized defaults to the usage amounts). Use it to write detection/e2e tests instead of hand-writing JSON. CLI tests monkeypatch `cli.assume_role_session`; `tests/test_pipeline.py` calls `pipeline.run` with a fake session. Tests that assert on the pre-provisional window build it with `Settings(include_provisional=False)`.

`demo/run_demo.py` runs the real `cli.main` with a temp AWS config, a simulated MFA code, and stubbed STS + paginated CE responses built from synthetic data with planted scenarios (SP/RI expiry, provisional spike, DROP, per-service override via `demo/cost-anomaly.toml`). It writes `demo/demo_anomalies.csv` plus the reports.
